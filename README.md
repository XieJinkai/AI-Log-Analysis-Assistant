# AI Log Analysis Assistant · 日志智能识别系统

Windows 本地单用户日志分析工具。以正常时序说明或正常日志作为参考，使用 **DeepSeek** 分析待检测日志，生成任务时序图、异常与疑点、可回查的证据，以及 Markdown 报告，并支持带原次日志上下文的连续追问。

> 没有记录到事件，不等于事件没有发生；时序偏离，也不等于已经找到根因。没有日志依据时，应明确说明无法推断。本工具用于辅助排查，不能代替人工复核。

## 功能

- 导入正常时序说明、正常运行日志和待检测日志，选择文件编码及分析行范围。
- 根据日志关联任务、参与方和事件，展示实际时序与正常参考时序。
- Mermaid 时序图预览、页面内全屏、缩放、源码查看及异常事件高亮。
- 区分已观察异常与疑似异常；集中窗口支持跨任务查看、任务和类型筛选、证据回查、时序定位。
- 继续追问本次分析，每次携带原次脱敏资料、分析报告与完整已完成问答。
- 导出含 Mermaid 源码的 `.md` 报告，本地自动保存工作区及聊天记录。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows，提供 PowerShell 和双击启动脚本 |
| Python | 3.11 或更高，命令需在 PATH 中 |
| Node.js | 22.12 或更高 |
| pnpm | 9 或更高，仓库包含锁文件 |
| 模型服务 | 自备有效的 DeepSeek API Key，以及可用账户额度 |
| 网络 | 安装依赖需要访问包源；分析、连接测试和追问需要连接 DeepSeek |

界面在本机浏览器使用，不要求安装桌面客户端。当前模型接口固定连接 `https://api.deepseek.com`，不支持切换其他供应商或自定义服务地址。

## 首次安装

在 PowerShell 中执行：

```powershell
git clone https://github.com/XieJinkai/AI-Log-Analysis-Assistant.git
cd AI-Log-Analysis-Assistant

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 尚未安装 pnpm 时执行；已经安装则跳过
npm install -g pnpm@10
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
```

仓库不包含 Python 虚拟环境、前端依赖或构建产物，首次克隆后必须完成以上步骤。下载 ZIP 的用户可解压后进入项目目录，从创建虚拟环境开始执行。

### 配置 DeepSeek

两种方式任选一种：

1. **配置文件**：将根目录 `.env.example` 复制为 `.env`，填写 `DEEPSEEK_API_KEY`，然后启动服务。不要覆盖已有 `.env`。
2. **页面配置**：直接启动服务，在右上角“模型配置”输入 API Key 并保存。此方式仅保存到当前服务内存，重启后需重新输入。

也支持启动进程的 `DEEPSEEK_API_KEY` 环境变量；非空 `.env` 配置优先。不要把真实 Key 填入 `.env.example`、README、源码、截图或提交记录。

程序默认模型标识为 `deepseek-flash`，不保证每个账户都可用。在“模型配置”中点击“测试连接”，按返回的可用列表设置模型。连接成功但提示所选模型不可用时，需要更换模型并保存。

上下文预算和输出预留也在此配置，输出预留必须小于上下文预算，且均需符合所选模型的实际限制。页面中的模型、预算和 Key 修改不会写回 `.env`，重启后恢复程序默认配置及启动时的 Key 来源。

## 启动与停止

首次安装完成后，双击 `start.cmd`，或执行：

```powershell
.\start.ps1
```

PowerShell 阻止脚本时，可为这一次启动执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

默认地址为 `http://127.0.0.1:8765`。端口占用时，脚本在后续 20 个端口中寻找空闲端口，**以终端打印的地址为准**。指定起始端口：

```powershell
.\start.ps1 -Port 8766
```

服务只监听本机。保持启动终端运行，按 `Ctrl+C` 停止；关闭浏览器不会停止后台服务。不要同时启动多个共享同一工作区缓存的实例，避免互相覆盖保存结果。

## 使用步骤

### 1. 导入资料

在左侧“分析资料”中添加或拖入文件：

| 位置 | 支持格式 | 是否必填 |
| --- | --- | --- |
| 正常时序说明 | `.md`、`.txt` | 与正常运行日志至少提供一种，也可同时提供 |
| 正常运行日志 | `.log`、`.txt` | 同上 |
| 待检测日志 | `.log`、`.txt` | 至少一份 |

正常时序说明最多 1 份；正常和待检测日志各最多 20 份。单文件不超过 20 MiB，当前导入资料合计不超过 50 MiB。这是导入上限，不代表模型能一次处理该体积。

文件默认尝试 UTF-8 和 GB18030，显示不正确时手动切换编码。二进制、受保护或无法解码的内容需先导出纯文本，不要只修改扩展名。

标准参考图需要包含 Mermaid `sequenceDiagram`，Markdown 中可用 mermaid 代码块包裹。标准图可直接预览；普通文字说明、正常日志会在分析后尝试由 AI 重建参考图，证据不足时不保证生成。

### 2. 选择范围与脱敏

勾选本轮文件，设置每份文件的起止行号。可填写“分析关注点”，例如“关注任务执行完成后，上报接口是否取得确认”。

自动脱敏处理常见 IP、邮箱及部分令牌；“自定义脱敏项”每行一项，按精确文本替换。自动脱敏可能遗漏敏感信息，必须人工检查发送预览。未勾选文件或所选范围之外的日志不参与本次分析。

### 3. 开始分析

点击“开始分析”，核对预览中的文件、行范围、脱敏内容和预算，勾选发送确认，再点“确认并开始分析”。

只有确认后才将资料发送至 DeepSeek。输入为全部选定行，不自动分块、截断、采样或删除内容。保守预算超限时拒绝发送，需要缩小范围或调整符合模型限制的预算。

同一服务同时只运行一个分析或追问。取消分析只能尽力中断本地请求，不能保证撤回云端已经接收的数据或免除费用。

### 4. 查看结果

- 在任务选择框中切换关联任务，分别查看“实际时序”“参考时序”和“事件记录”。
- 使用时序图工具栏查看源码、缩放或全屏；退出按钮和 `Esc` 返回原视图。
- 右侧“异常与疑点”列出当前任务发现，展示观察事实、预期依据、原因推测、不确定性和核查建议。
- 标题右侧窗口按钮打开“集中查看”，汇总全部任务，可按任务、已观察异常和疑似异常筛选。
- 点击异常定位相关时序；点击证据引用查看原始行号，可切换已发送脱敏副本和本地原文。

“已观察异常”仅表示日志支持该现象，**不代表根因已证实**。无确认异常不能理解为所有日志正常；结果只适用于本次已发送范围。部分模型输出未通过校验时会明确标记不完整，并隔离无效条目。

### 5. 继续追问

分析产生结果后，点击“分析追问”，输入问题，勾选云端发送确认。例如：

- “这个任务是执行失败，还是执行完成但上报未确认？请引用日志。”
- “现有日志能确认远端没收到吗？还缺少哪些证据？”
- “沿用上个问题，应该按哪个任务号或请求号补查日志？”

每轮发送原次所选脱敏日志快照、参考、报告、关注点及全部已完成问答，不仅发送报告摘要。修改左侧当前文件不会改变已有分析的上下文。超出预算时明确拒绝，不静默删掉历史。

关闭窗口不会清空，也不会停止正在生成的回答；需要中断时点击“停止回答”。失败或取消的回答不作为下一轮已完成历史。历史回答不是新证据，回答中的引用仍需通过本地校验。

**清空时机**：刷新页面、重启服务、关闭窗口不清空；只有确认发送且新分析成功受理后，才清空此前追问。返回修改、无效输入、预算不足或新分析未能受理不会清空。需要保留的重要回答请在开始新分析前自行记录，报告导出不包含追问记录。

### 6. 导出报告

点击“导出 .md”，保存本次报告、证据和时序图源码。Mermaid 图需要在支持 Mermaid 的 Markdown 查看器中渲染。旧报告可从左侧分析记录入口打开，最多保留最近 5 次分析；新分析清空旧追问不等于删除保留范围内的旧报告。

## 数据保存与安全

| 内容 | 保存方式 |
| --- | --- |
| 启动 Key | 本地 `.env` 或进程环境变量 |
| 页面输入的 Key | 当前服务内存，不写入工作区缓存 |
| 导入文件、原始及脱敏快照、分析报告、追问、自定义脱敏项 | `artifacts/workspace.sqlite3` |

工作区缓存**未加密，包含日志原文**；`.env` 同样是本地明文。不要提交、共享或上传这些文件，限制目录访问权限。更新代码或重新构建前端不要求删除缓存。

服务中断后，未完成分析或追问会标记失败，不自动向云端重发；已完成记录可恢复。缓存损坏会明确报错并保留原文件，不自动清空。备份缓存前先停止服务；手动清理缓存会丢失工作区记录，应先备份并导出所需报告。

本地只校验模型输出结构、引用的文件/行号/原文及必要关联，不保证语义判断或推测正确。引用存在不等于因果成立，需人工复核。模型结构或引用不合格时，最多额外调用一次修复，可能增加费用。

本软件没有多用户身份认证，不是公网部署方案。不要改为监听公网，也不要通过反向代理直接公开。已在聊天、截图或公开位置出现过的 Key 建议立即轮换。

## 常见问题

| 问题 | 处理方式 |
| --- | --- |
| `Missing .venv` | 在项目根目录创建虚拟环境并安装 requirements.txt |
| `Missing frontend build` | 执行 pnpm 安装依赖及 frontend build，首次安装不能只双击启动 |
| pnpm 的 PowerShell 脚本被阻止 | 可用 `pnpm.cmd` 替代 `pnpm`；不要为此永久降低系统执行策略 |
| 浏览器无法打开 | 检查启动终端仍在运行，使用实际打印的端口；不要假定始终是 8765 |
| 开始分析不可用 | 至少选中一份正常参考和一份待检测日志；等待当前分析/追问结束 |
| Key 无效、余额不足、限流 | 检查配置和账户状态，稍后手动重试；不要把密钥贴入问题反馈 |
| 模型不可用或请求参数无效 | 测试连接后选账户可用模型，核对该模型支持的预算与接口参数 |
| 无法连接 DeepSeek | 检查本机到 API 的网络；当前客户端不自动使用系统代理环境变量 |
| 上下文预算超限 | 减少选中文件/行范围，或调整有效预算；不会自动省略内容 |
| 模型输出被截断 | 在模型允许范围内增加输出预留，或缩小资料范围后重试 |
| 引用校验失败或报告不完整 | 按提示复查资料与范围，不将不完整结果当作确定结论 |
| 参考无法直接预览 | 确认是 sequenceDiagram；纯文本说明需经分析尝试重建 |
| 配置修改后显示旧结果 | 已完成报告不自动重算，需要确认并启动新的分析 |

## 本地开发

后端采用 FastAPI/Pydantic，前端采用 React/TypeScript/Vite，时序图使用 Mermaid，缓存使用 Python 标准库 SQLite。

后端开发服务：

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8765
```

另开终端运行前端：

```powershell
pnpm --dir frontend dev
```

打开 Vite 打印的前端地址。开发代理默认将 `/api` 转发到 8765；后端更换端口时同步修改 `frontend/vite.config.ts`。后端拒绝直接跨源写请求，不要绕过同源保护。日常使用推荐先构建前端，再运行 start.cmd 的单服务模式。

更新前端后重新执行 `pnpm --dir frontend build`，刷新浏览器；修改后端后重启服务。提交前检查暂存内容，确保不包含 `.env`、`artifacts/`、依赖目录、构建产物或真实业务日志。
